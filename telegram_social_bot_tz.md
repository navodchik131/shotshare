# Telegram Social Bot

## Описание системы

Это Telegram-бот, который создает внутри Telegram социальную систему для обмена контентом между пользователями. Основная цель: пользователи делятся фото/видео по ежедневным заданиям, получают просмотры и шанс на рост подписчиков своих каналов (если они их создают). Система включает честное распределение постов, случайные слоты, модерацию и минимальную админку для управления.

---

## Основные компоненты

1. **Пользователи**: регистрируются в боте, получают задания, отправляют фото/видео, просматривают контент других пользователей.
2. **Контент**: фото или видео до 10 секунд. Не обязательно привязывать канал. Контент участвует в ежедневной сессии.
3. **Сессия**: ежедневный цикл. Включает прием контента, распределение постов и просмотры пользователями.
4. **Админка**: интерфейс для управления заданиями, просмотра статистики, обработки жалоб.
5. **Модерация**: система жалоб пользователей + автоматические проверки (nudity, насилие, запрещёнка).
6. **Случайные слоты**: 2–3 поста на сессию, показываемые всем пользователям, создают элемент неожиданности и дофамин-эффект.

## Пользовательский сценарий

### 1. Регистрация
- Пользователь запускает бота.
- Бот приветствует и предлагает зарегистрироваться.
- Запрашиваются:
  - Имя или ник
  - (Необязательно) ссылка на канал Telegram
- Пользователь подтверждает.
- Запись добавляется в базу пользователей с полем `активен = true`.

### 2. Получение задания
- Каждый день бот проверяет список активных пользователей.
- Админ задает ежедневное задание (через админку) или используется повторяющееся базовое задание.
- Бот рассылает уведомление:
  > "Сегодняшнее задание: [текст задания]"
- Пользователь нажимает "Принять".

### 3. Отправка контента
- Пользователь отправляет фото или видео (≤10 секунд).
- Бот проверяет базовые критерии формата.
- Если контент не соответствует формату, бот отправляет уведомление об ошибке.
- Контент сохраняется в базе и участвует в сессии.

### 4. Просмотр контента других пользователей
- После окончания периода приема контента бот распределяет посты:
  - **Честные слоты:** 2–3 поста по формуле N / M (число пользователей / число авторов), каждый автор получает гарантированные показы.
  - **Случайные слоты:** 2–3 поста, случайно выбранные из всех авторов, показываются всем пользователям.
- Лимит показов на пользователя: например, 5 постов за сессию.
- Пользователь может ставить лайк/подписаться на канал автора, если канал есть.

### 5. Жалобы и модерация
- Если пост не соответствует заданию, пользователь может пожаловаться.
- Правила:
  - 3 жалобы → пост отправляется в модерацию.
  - Модерация принимает решение:
    - одобрить → пост остается
    - удалить → пост исчезает
    - санкция автору → блок на 1 день / сессию / повторная блокировка аккаунта при повторении

### 6. Проверка активности пользователей
- Каждое утро бот отправляет уведомление:
  > "Участвуешь сегодня?"
- Если уведомление не доставлено → пользователь помечается как неактивный.
- 2–3 дня подряд неактивен → исключение из базы или не учитывается при распределении постов.

## Админка

### Основные функции
1. **Управление заданиями**
   - Создание нового задания
   - Редактирование задания
   - Выбор даты и времени для отправки
2. **Статистика пользователей**
   - Количество зарегистрированных
   - Количество активных
   - Сколько отправили контент
   - Сколько просмотрели посты
3. **Модерация постов**
   - Список постов с жалобами
   - Просмотр автора, даты, текста задания
   - Принятие решений: удалить/оставить/санкция
4. **Случайные слоты**
   - Админ видит, какие посты будут показаны как случайные
   - Возможность ручного изменения, если необходимо

## Технические требования

1. **База данных**
   - Пользователи: ID, имя, канал (опционально), активен/неактивен, статистика участия
   - Посты: ID, автор, дата, тип (честный/случайный), медиа (ссылка), статус (одобрен/удалён), количество жалоб
   - Задания: ID, текст, дата/время, активный/неактивный

2. **Модерация**
   - Авто-фильтры: nudity, насилие, запрещёнка (с помощью Vision API или аналогов)
   - Жалобы пользователей → триггер на ручную модерацию
   - История санкций для каждого пользователя

3. **Логика рассылки постов**
   - Выбор участников честных слотов: N / M распределение
   - Выбор случайных слотов: 2–3 поста из всех авторов, показываемые всем
   - Лимит показа постов на пользователя за сессию (например, 5)

4. **Телеграм API**
   - Уведомления пользователям о заданиях
   - Отправка постов
   - Отслеживание ошибок доставки (бот заблокирован, пользователь не активен)
   - Inline кнопки для "Принять задание", "Пожаловаться", "Подписаться"

5. **Админский интерфейс**
   - Можно сделать в виде отдельного бота или веб-панели
   - Просмотр статистики, управление заданиями, модерация

---

## MVP Flow (от старта до первой сессии)

1. Пользователь запускает бота → регистрация → подтверждение
2. Админ создает задание через админку (текст + время рассылки)
3. Бот уведомляет всех активных пользователей о задании
4. Пользователи отправляют контент (фото/видео)
5. Бот проверяет базовый формат и сохраняет контент
6. После окончания приема контента:
   - Распределяются честные слоты
   - Распределяются случайные слоты
7. Пользователи просматривают посты, могут лайкать, подписываться на каналы
8. Пользователи могут жаловаться на несоответствие контента
9. Модератор проверяет посты с жалобами, принимает решение → санкции при необходимости
10. Утром следующего дня проверяется активность пользователей → корректировка базы

---

## Особенности

- Каналы пользователей **не обязательны**, контент может публиковаться без канала.
- Элемент случайности (рандомные слоты) создает дополнительный интерес и дофамин-эффект.
- Повторяемые базовые задания позволяют поддерживать активность без исчерпания идей.
- Принцип саморегуляции через жалобы минимизирует необходимость постоянной модерации.
- Админка позволяет вести статистику, управлять заданиями и контролировать систему.
