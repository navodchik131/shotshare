# Анализ хранения медиа файлов

## Текущая ситуация

**Файлы НЕ хранятся на диске!** 

Сейчас система использует только `file_id` от Telegram - это уникальный идентификатор файла в Telegram, который позволяет отправлять файл пользователям без необходимости его скачивать.

### Как это работает сейчас:

1. Пользователь отправляет фото/видео боту
2. Бот получает `file_id` от Telegram
3. Бот сохраняет только `file_id` в базе данных
4. При отправке поста другим пользователям используется `file_id` для отправки файла через Telegram API

### Преимущества текущего подхода:

✅ **Экономия дискового пространства** - файлы не занимают место на сервере
✅ **Быстрая работа** - не нужно скачивать/загружать файлы
✅ **Масштабируемость** - можно иметь миллионы постов без проблем с диском
✅ **Простота** - не нужно управлять файлами, удалять старые и т.д.

### Недостатки и риски:

⚠️ **Зависимость от Telegram** - если Telegram удалит файл или file_id станет недействительным, файл будет потерян
⚠️ **Ограничения Telegram** - файлы хранятся в Telegram только определенное время (обычно долго, но не гарантированно)
⚠️ **Нет резервных копий** - если что-то случится с Telegram, файлы могут быть потеряны
⚠️ **Проблемы с админкой** - для просмотра в админке нужно каждый раз запрашивать файл у Telegram

## Варианты решения

### Вариант 1: Текущий подход (file_id только) - РЕКОМЕНДУЕТСЯ для MVP

**Когда использовать:**
- MVP/стартап с ограниченным бюджетом
- Не критично долгосрочное хранение
- Готовы принять риск потери старых файлов

**Что делать:**
- Оставить как есть
- Мониторить ошибки при отправке постов (если file_id недействителен)
- В будущем можно добавить миграцию на вариант 2 или 3

### Вариант 2: Гибридный подход (file_id + опциональное скачивание)

**Когда использовать:**
- Нужна надежность, но бюджет ограничен
- Хотите сохранять только важные файлы

**Что делать:**
- Использовать file_id по умолчанию
- Скачивать файлы только для постов со статусом APPROVED после дедлайна
- Удалять локальные файлы для удаленных/отклоненных постов
- Настроить автоматическую очистку старых файлов (например, старше 30 дней)

**Оценка места:**
- Фото: ~2-5 МБ каждое
- Видео (10 сек): ~5-15 МБ каждое
- При 1000 активных пользователей, 1 пост в день: ~7-20 ГБ в месяц
- При 10,000 пользователей: ~70-200 ГБ в месяц

### Вариант 3: Полное локальное хранение

**Когда использовать:**
- Критично долгосрочное хранение
- Нужна независимость от Telegram
- Есть бюджет на хранилище

**Что делать:**
- Скачивать все файлы при загрузке
- Хранить на диске или в облачном хранилище (S3, Yandex Object Storage и т.д.)
- Использовать CDN для быстрой раздачи
- Настроить автоматическую очистку старых файлов

**Оценка места:**
- Те же цифры, что в варианте 2
- Плюс нужен бэкап и резервное копирование

### Вариант 4: Облачное хранилище (S3, Yandex Object Storage)

**Когда использовать:**
- Нужна надежность и масштабируемость
- Есть бюджет на облачное хранилище
- Хотите избежать проблем с диском на сервере

**Что делать:**
- Скачивать файлы при загрузке
- Загружать в облачное хранилище (S3, Yandex Object Storage, Cloudflare R2)
- Хранить URL или ключ в базе данных
- Использовать CDN для раздачи

**Стоимость (примерно):**
- Yandex Object Storage: ~1-2 руб/ГБ в месяц
- AWS S3: ~$0.023/ГБ в месяц
- Cloudflare R2: бесплатно до 10 ГБ, потом ~$0.015/ГБ
