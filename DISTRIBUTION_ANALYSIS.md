# Анализ ситуаций, когда пользователь может не получить постов

## Проблемная ситуация: 3 пользователя, все отправили посты

### Исходные данные:
- **Пользователи**: A, B, C (все активны)
- **Авторы**: A, B, C (все отправили по 1 посту)
- **Честные слоты**: по 1 посту от каждого автора (3 поста)
- **Случайные слоты**: 0 (все посты ушли в честные)

### Логика распределения честных слотов:

**Для автора A:**
- Получатели: [B, C] (2 человека, исключаем A)
- `slots_per_author = max(1, 2 // 3) = max(1, 0) = 1`
- Выбирается 1 случайный получатель из [B, C]
- **Результат**: Пост A показывается либо B, либо C (случайно)

**Для автора B:**
- Получатели: [A, C] (2 человека, исключаем B)
- `slots_per_author = 1`
- Выбирается 1 случайный получатель из [A, C]
- **Результат**: Пост B показывается либо A, либо C (случайно)

**Для автора C:**
- Получатели: [A, B] (2 человека, исключаем C)
- `slots_per_author = 1`
- Выбирается 1 случайный получатель из [A, B]
- **Результат**: Пост C показывается либо A, либо B (случайно)

### Проблема: случайная выборка может исключить пользователя

**Пример плохого распределения:**
- Пост A → показывается B
- Пост B → показывается A
- Пост C → показывается A

**Результат:**
- Пользователь A получил: пост B, пост C (2 поста) ✅
- Пользователь B получил: пост A (1 пост) ✅
- Пользователь C получил: **НИЧЕГО** ❌

### Почему это происходит?

1. **Случайная выборка**: `random.sample(recipients, num_recipients)` не гарантирует, что все получатели будут выбраны
2. **Формула дает мало получателей**: `slots_per_author = 1` означает, что каждый пост показывается только 1 человеку
3. **Нет проверки покрытия**: Система не проверяет, получил ли каждый пользователь хотя бы 1 пост

## Другие проблемные ситуации:

### Ситуация 1: Пользователь - автор всех случайных постов
- Если случайные посты от одного автора (например, A)
- Пользователь A не получит случайные посты (он их автор)
- Если A также не попал в честные слоты → **0 постов**

### Ситуация 2: Малое количество пользователей
- При 2 пользователях: если оба авторы, каждый может получить только 1 пост (от другого)
- При 4 пользователях и 3 авторах: `slots_per_author = max(1, 3 // 3) = 1`
- Один из получателей может не получить пост

### Ситуация 3: Неравномерное распределение авторов
- Если 5 пользователей, но только 2 отправили посты
- `slots_per_author = max(1, 4 // 2) = 2`
- Каждый пост показывается 2 пользователям
- Но если случайная выборка повторяется → некоторые могут получить больше, другие меньше

## Решение проблемы:

### Вариант 1: Гарантировать минимум 1 пост каждому
- Перед отправкой проверить, получил ли каждый пользователь хотя бы 1 пост
- Если нет - добавить недостающие посты

### Вариант 2: Равномерное распределение вместо случайного
- Использовать round-robin или равномерное распределение
- Гарантировать, что каждый получатель получит примерно одинаковое количество постов

### Вариант 3: Улучшить формулу для малого количества
- При малом количестве пользователей (≤5) использовать другую логику
- Например, показывать каждый пост всем получателям (кроме автора)

### Вариант 4: Увеличить количество получателей на пост
- Вместо `slots_per_author = max(1, recipients // authors)` использовать `min(recipients, authors + 1)`
- Гарантировать больше получателей на пост

## Рекомендация:

**Исправить логику распределения**, чтобы:
1. Каждый активный пользователь получил хотя бы 1 пост (если есть посты)
2. Распределение было более равномерным
3. При малом количестве пользователей показывать посты всем (кроме автора)
